# Ambient music beds (T11)

Six calm ambient instrumental beds used as quiet background music under
narration in social video renders.

## Provenance

- **Provider:** none. No generative-audio service or third-party music
  library was reachable from the environment that produced these files.
  They are **synthesized in-repo with ffmpeg** (layered sine-wave
  partials forming a chord, a slow amplitude LFO, and a static lowpass
  filter — no samples, no recordings, no loops sourced from anywhere).
- **Generated by:** `social/scripts/generate-beds.ts`, run with:
  ```
  npx tsx social/scripts/generate-beds.ts
  ```
- **Date:** 2026-08-25
- **Licence:** Original work. © Split Atom Labs. Same terms as the rest
  of this repository. Because these files are pure algorithmically
  synthesized waveforms with no third-party input, there is **no
  Content ID fingerprint and no third-party rights attached** — nothing
  to license, clear, or dispute.
- **One-off generation path:** this script is run manually, once (or
  whenever the bed set is deliberately revised). The daily render job
  must **never** call `generate-beds.ts` — downstream code reads the
  already-committed files below via `social/src/audio/beds.ts`.
- **Determinism:** the script is fully deterministic (no timestamps, no
  RNG). Re-running it on the same machine with the same ffmpeg version
  reproduces byte-identical files (verified: `ffmpeg version 8.1.1`,
  Homebrew, macOS).
- **Format:** FLAC (lossless), 48kHz stereo, 16-bit. A 16-bit WAV set at
  this sample rate/duration/channel count would be ~11.5MB per file
  (~69MB total for six); FLAC brings the full set to about **14MB**
  total. The downstream mixer (T15) re-encodes into the final mix, so
  losslessness here matters more than container choice.

## How they were built

Each bed is a stereo mix of 4 sine-wave chord tones plus a slow
amplitude ("breathing") LFO and a gentle static lowpass filter — no
percussion, no vocals, no sudden events.

**Seamless looping:** every partial frequency and every LFO rate is
quantized to an exact multiple of 1/60 Hz, so the underlying waveform
mathematically repeats every 60.000s. The lowpass filter is stateful,
so naively rendering exactly 60s from a cold filter start would not
loop cleanly (the filter's startup transient at t=0 doesn't match its
settled state at t=60s). To avoid that, each bed is actually rendered
across 66s (a 6s pre-roll + the 60s kept window), with the lowpass
running continuously the whole time so its transient decays away
(audio-filter time constants here are well under a millisecond — 6s is
enormous headroom) before the `[6s, 66s)` window is trimmed out. See
the comment header in `generate-beds.ts` for the full reasoning.

Verified after generation:
- `ffprobe`: all six report `48000 Hz`, `channels=2`, `duration=60.000000`.
- `ffmpeg -af volumedetect`: max_volume is -12.5 to -14.7 dBFS across all
  six (no clipping, consistent quiet level — well under narration level;
  full loudness normalization of the final mix happens in T15).
- Loop join: compared the last 5 samples to the first 5 samples of each
  file; the wrap-around sample-to-sample delta matches the file's own
  internal sample-to-sample deltas (no discontinuity/click at the loop
  point).
- Re-ran the generator into a scratch directory and `cmp`'d the output
  against the committed files: byte-identical.

## The six beds

| File | Root | Chord quality | Register | LFO rate | LFO period | Lowpass cutoff | Duration |
|---|---|---|---|---|---|---|---|
| `bed-01-c-major9.flac` | C | major add9 | C3 | 0.0333 Hz | 30s | 900 Hz | 60.000s |
| `bed-02-d-minor9.flac` | D | minor add9 | D3 | 0.0500 Hz | 20s | 1100 Hz | 60.000s |
| `bed-03-e-minor7.flac` | E | minor7 | E2 (lowest, warmest) | 0.0667 Hz | 15s | 750 Hz | 60.000s |
| `bed-04-f-major7.flac` | F | major7 | F3 (airiest) | 0.1000 Hz | 10s | 1400 Hz | 60.000s |
| `bed-05-g-sus4.flac` | G | sus4 | G3 | 0.0167 Hz | 60s (one swell/loop) | 1000 Hz | 60.000s |
| `bed-06-a-minor.flac` | A | minor (+ high sus2 colour tone) | A2 (lowest, most active) | 0.1333 Hz | 7.5s (most active) | 1250 Hz | 60.000s |

Root note, chord quality, register, and breathing (LFO) rate are all
distinct across the six, so a viewer who sees several posts in a week
does not hear the same bed on repeat.

## Selecting a bed

`social/src/audio/beds.ts` provides `listBeds()`, `bedPath(id)`, and a
deterministic `selectBed(seed)` for downstream code — see that file's
doc comments for the selection contract.
