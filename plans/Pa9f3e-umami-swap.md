# Swap Analytics to Umami Cloud

## Objective
Replace Vercel Web Analytics with Umami Cloud so custom events work on the free tier without requiring a cookie-consent banner.

## Decisions
- **Provider:** Umami Cloud free tier (100k events/mo). Drop-in `<script>`, no npm package.
- **Script tag** lives in `web/src/routes/+layout.svelte` inside `<svelte:head>`. Gated on `PUBLIC_UMAMI_WEBSITE_ID` — if unset, no script renders (so forks/previews don't leak into the prod dashboard).
- **Env var:** `PUBLIC_UMAMI_WEBSITE_ID` via SvelteKit's `$env/static/public`. Website ID is a UUID and is safe to expose client-side (it's public by design; every Umami site reveals it in-page).
- **Auto-tracked pageviews** stay on (Umami's default). Custom events fire through the existing `trackEvent` wrapper — call sites in `progress.js`, `ShareButton.svelte`, `tags/[tag]/+page.svelte`, `[book]/+page.svelte`, `completed/[book]/+page.svelte` are untouched.
- **DNT:** use `data-do-not-track="true"` on the script tag. Remove the redundant `navigator.doNotTrack` check from `analytics.js` (Umami honours DNT directly; two layers is noise).
- **No `data-cache`** — enabling it writes a visitor ID to localStorage and breaks the consent-free posture.
- **Full swap.** Remove `@vercel/analytics` entirely. Running two analytics tools is not worth it.
- **Dev gating** stays in `analytics.js` (same `!dev` guard) so custom events don't fire locally. Auto-pageviews will still hit Umami in dev unless gated at the script tag too — include the `PUBLIC_UMAMI_WEBSITE_ID` check server-side via `dev` to also skip script injection in dev.

## Files
- `web/src/lib/analytics.js` — swap `window.va('event', { name, ...props })` → `window.umami?.track(name, props)`; drop DNT check.
- `web/src/routes/+layout.svelte` — add `<svelte:head>` block with Umami `<script defer>` using `PUBLIC_UMAMI_WEBSITE_ID`; gated on `!dev && id`.
- `web/src/routes/+layout.js` — remove `injectAnalytics` import + call; keep `prerender = true`.
- `web/package.json` — remove `@vercel/analytics` from dependencies.
- `web/package-lock.json` — regenerated by `npm install`.
- `web/tests/e2e/analytics.spec.js` — replace `window.va` stub with `window.umami = { track: (...args) => ... }`; update filter from `c[0] === 'event'` to match new call shape.
- `docs/ANALYTICS.md` — update "Tools" and "Implementation Notes" sections. Event table stays.
- `web/.env.example` (new) — document `PUBLIC_UMAMI_WEBSITE_ID`.

## Constraints
- No regressions to the 8 existing events or their properties (see `docs/ANALYTICS.md`).
- Full e2e suite passes (`web/tests/e2e/analytics.spec.js` must continue to capture `book_landing_viewed`, `book_started`, `engaged_session`).
- No new cookies or localStorage keys written by analytics code. `plain:*` localStorage keys used by the first-session state remain — they pre-existed and are not tracking identifiers.
- User must manually (out of repo):
  1. Create Umami Cloud account + website entry → grab website ID UUID.
  2. Set `PUBLIC_UMAMI_WEBSITE_ID` in Vercel → Settings → Environment Variables for Production + Preview.
  3. After the code deploy, verify `/api/send` requests in Network tab and confirm events appear in the Umami dashboard.
